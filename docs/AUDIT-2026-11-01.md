# Production-readiness audit (2026-11-01)

Audited `main` @ `0180333`. Audit only: no code, migrations or services were changed. No secrets read.

## Tests
- lint ✅ · `npm test` 10/10 ✅ · build ✅ · `npm run test:db` 57/57 ✅ (local throwaway Postgres)
- Live: 23 tables, all with RLS. Vercel: `SUPABASE_SERVICE_ROLE_KEY` and `ENROLLMENT_WEBHOOK_SECRET` set (Production only).

## High
- **H1. Parent invite codes can be guessed** (6 hex = 16.7M combinations; no rate limit) → a stranger can read a child's
  profile and progress and set `guardian_consent_at`; a student can also "consent" for themselves via a second account.
  Where: `profiles.invite_code`, `complete_onboarding('parent')`, `link_child`. Fix: long expiring codes, attempt
  limits, confirmation by student or parent OTP. **Migration: yes.**
- **H2. Purchase claim matches an unverified parent phone** → anyone who knows a paying parent's number can take the
  seat. Where: `claim_purchases`, `_record_purchase` (`profiles.guardian_phone`). Fix: auto-unlock only on a verified
  email/phone; phone-only matches go to Studio for approval or OTP. **Migration: yes.**
- **H3. Any teacher code = full paid course free**, all courses. Where: `has_course_access` (any teacher),
  `complete_onboarding('teacher')`. Fix: Studio approves teachers; access limited to school-licensed courses; rotate
  codes. **Migration: yes.**

## Medium
- **M1. Open redirect after login.** `src/app/login/page.js` uses `?next` unchecked; the check
  `startsWith("/") && !startsWith("//")` in `onboarding/page.js`, `src/proxy.js` and `lib/supabase/server.js` accepts
  `/\evil.com` (browsers open it as https://evil.com, confirmed). Fix: one shared same-origin `safeNext()`. Migration: no.
- **M2. Students can write their own progress and answers for any lesson**, including locked ones, and add
  unlimited correct answers (XP). RLS "write/update own progress" (`lesson_progress`), "write own answers"
  (`checkpoint_answers`). This corrupts pipeline stage 4 and future certificates. Fix: checked RPCs requiring
  `can_watch_lesson`, answer caps, server-side XP. **Migration: yes.**
- **M3. Quiz answers can be harvested:** `submit_quiz` returns correct answers on every attempt, with unlimited
  attempts. Fix: reveal only after a pass or N attempts; cooldown; shuffle. **Migration: yes.**
- **M4. Minors' consent and data rights (DPDP):** weak consent (see H1); no export/delete flow; leads and personal
  data kept indefinitely. **Migration: yes** (retention and deletion).
- **M5. No backups / no error alerts / 1-hour logs** (Supabase free, Vercel Hobby; Hobby terms forbid commercial
  use). Fix: nightly pg_dump (GitHub Actions) or Supabase Pro; Sentry; Vercel Pro before taking payments.
- **M6. Both GitHub repos are public.** Make them private.
- **M7. Website payment doesn't unlock the LMS:** `beyond-tatva-web/api/verify-payment.js` never calls
  `/api/enrollments`; no Razorpay webhook or refunds. Codex task (docs/website-enrollment.md).

## Low
- L1 Submissions bucket accepts uploads to any folder under the student's own ID (storage abuse). Tighten the path rule. Migration: yes.
- L2 Student school code `slug-XXX` = 46,656 combinations (`createSchool`). Longer codes.
- L3 Secrets are Production-only, so Preview deployments fail on `/api/enrollments` and `/api/leads`.
- L4 Paid YouTube/Drive links can be shared (Bunny signed links, on hold).
- L5 Signed API requests can be replayed within 5 minutes (harmless: the reference makes it a duplicate).
- L6 `admin_pipeline` full scan: fine up to ~1k students; index or page it later.

## Speed
- `claim_purchases` runs on every page for free students (`lib/supabase/server.js`): run it only at sign-in or on /unlock.
- `getCourse` is not cached; cache it and refresh on Studio save.
- Advisors: 8 unindexed foreign keys, 16 tables with duplicate permissive read policies.
